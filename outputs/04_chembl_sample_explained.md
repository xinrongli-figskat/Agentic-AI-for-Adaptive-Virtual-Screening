# 第一次 ChEMBL 真实数据读取：逐项解释

整理日期：2026-10-14。依据：用户在远程终端贴出的首次样本摘要，以及 `inspect_chembl_sample.py` 0.1.0 的统计逻辑。此文将此前聊天中的详细解释整理成独立文档；尚未逐行核验该样本的原始记录。示例数据和示例阈值均不是实际样本或已确定的项目规则。

## 1. 读到的是哪种数据

ChEMBL 汇集公开的化合物生物活性证据。我们的脚本先读取数据库状态，再读取默认 API 顺序下的前 20 条 activity 记录。数据库状态返回版本 ChEMBL_37；读取 activity 时指定 `limit=20`、`offset=0`，没有指定靶点，也没有翻页。

一条 activity 可以理解为：“某个化合物，在某个实验中，针对某个目标或生物系统，得到了某种测量结果。”记录通常带有化合物 ID、结构、靶点 ID、实验 ID、文献 ID，以及测量类型、关系符号、数值和单位。

所以一条记录不是一个独立化合物，也不一定对应一次可作为本项目答案的直接结合实验。同一化合物可以在不同 assay、不同靶点或不同测量条件下出现多次。

下面是假设的例子，用于理解数据形式：

| 化合物 | 靶点 | assay | 测量 | 关系 | 数值 | 单位 |
|---|---|---|---|---|---|---|
| A | P | E1 | IC50 | = | 100 | nM |
| A | P | E2 | IC50 | = | 0.2 | uM |
| A | Q | E3 | IC50 | > | 10000 | nM |
| B | P | E1 | IC50 | = | 500 | nM |
| C | P | E1 | IC50 | 缺失 | 缺失 | nM |

这个表有五条记录、三个化合物。即使将 0.2 uM 换成 200 nM，也不能未经实验条件审查就与另一条结果合并。C 缺少结果，不能自动标成非活性。

## 2. 为什么先做这一步

项目最后要形成一个固定的化合物池，并为每个可查询化合物保存有明确含义的结果。搜索智能体每次查询一个化合物，由受控接口揭示它的结果。

如果数据构建时把不同实验含义混在一起、把重复记录当成不同化合物，或者把缺失值当作非活性，后面的“找到多少个命中”就会失去明确含义。

因此，这一步先检查能否获取真实数据、保留来源并理解字段。它是数据整理的准备工作，尚未选择合格靶点、制定命中标签或接入 LLM 智能体。当前 API 顺序样本也不能代表全库或任何靶点的分布。

## 3. 用途、采样说明和标签标记

| 字段 | 返回结果 | 怎样得出 | 意义 |
|---|---|---|---|
| purpose | exploratory_field_inspection_only | 脚本固定写入 | 声明用途是探索字段，不是正式评价数据集 |
| sampling | API order; not a random or representative sample | 脚本固定写入，对应当前默认顺序读取方式 | 这 20 条不是随机抽样，不应据其比例推断全库 |
| labels_assigned | false | 脚本固定写入；未执行标签生成 | 我们没有给这批记录分配项目的命中或非活性标签 |

`labels_assigned=false` 并不意味着来源数据库没有任何活性描述。它只说明我们的工具没有按照项目规则生成标签。这三个字段是用途声明，不是数据质量检测的分数。

## 4. 记录数、化合物数、靶点数和实验数

| 字段 | 结果 | 计算方式 | 能说明什么 |
|---|---|---|---|
| records_received | 20 | 返回 activities 列表的长度 | 这次实际拿到了 20 条记录 |
| api_total_matching_records | 24,527,044 | API 响应的 page_meta.total_count | 当前请求条件匹配的记录总数；不是我们下载的数量，也不是独立化合物数 |
| unique_molecules_with_ids | 7 | 对非空 molecule_chembl_id 去重计数 | 20 条记录涉及七个不同化合物 ID |
| repeated_molecule_records | 13 | 非空化合物 ID 的记录数减去不同 ID 数：20−7 | 超出每个 ID 首次出现的记录数；不等于发现了 13 条错误数据 |
| unique_targets_with_ids | 11 | 对非空 target_chembl_id 去重计数 | 出现了 11 个不同目标 ID；尚未验证是否都对应单一蛋白 |
| unique_assays_with_ids | 15 | 对非空 assay_chembl_id 去重计数 | 出现了 15 个实验记录 ID；不等于已经证明有 15 种不同实验技术 |

按化合物 ID 去重不等于完成了分子结构标准化。盐型、结构表示、立体化学以及不同 ID 是否应合并，仍需单独定义规则。多 assay 中的重复记录可能提供有用重复证据，也可能冲突；现在没有删除它们。

## 5. 缺失字段

脚本将字段不存在、值为 `None` 或空字符串 `""` 计为缺失。它不是对各种异常文本的完整质量检查。

| 字段 | 缺失记录数 | 浅显解释 |
|---|---|---|
| molecule_chembl_id | 0 | 每条都有化合物 ID |
| canonical_smiles | 0 | 每条都有结构字符串；尚未验证字符串能否解析以及结构是否合适 |
| target_chembl_id | 0 | 每条都有目标 ID；尚未验证映射是否符合项目要求 |
| assay_chembl_id | 0 | 每条都有实验 ID，便于进一步查实验描述 |
| document_chembl_id | 0 | 每条都有来源文献 ID；不意味着有 20 篇不同文献 |
| standard_value | 1 | 有一条缺测量值，不能直接拿来按阈值分类 |
| standard_relation | 1 | 有一条缺关系符号，不能擅自补成等号 |
| standard_units | 0 | 每条都有单位；不意味着它们的测量含义相同 |

数值缺失的那条和关系缺失的那条是否为同一条，需要看逐行数据。摘要给的是每个字段各自的计数。

## 6. 数字与边界值

`finite_numeric_value_count=19` 表示有 19 条的 standard_value 能转成有限数字。脚本使用 Decimal 检查是否是有限数，而不是检查它是否为有效药理学测量。数值为零或负数也可能通过这个数字检查；是否科学可用，需要结合测量类型判断。

这 19 条不等于 19 个精确活性值。带 `>` 或 `<` 的记录也可能有一个可解析的数字，这个数字表示边界。

`censored_record_count=5` 是关系符号属于 `<`、`<=`、`>`、`>=` 的记录数。本样本有四条 `>` 和一条 `<`。它们占本样本的 25%，不能把这个比例外推到全库。

例如 `IC50 > 10000 nM` 表示来源只给出下界信息，不能改写成 IC50 恰好等于 10000 nM。

## 7. 测量类型

`standard_type_counts` 是逐条读取 standard_type，再按相同文本计数。结果共 20 条：

| 类型 | 数量 | 如何理解 |
|---|---|---|
| IC50 | 11 | 某个指定实验读出被抑制到相应 50% 水平的浓度；需要实验条件才能解释，不能单凭名称断定直接结合 |
| EC50 | 1 | 产生相应半最大效应的浓度；具体效应由 assay 定义 |
| CC50 | 1 | 细胞毒性相关的 50% 浓度指标；具体读出和计算方式要看实验 |
| % remaining | 3 | 某个读出剩余的百分比；需要知道读出是什么、测量浓度和对照 |
| Selectivity index | 1 | 选择性相关指数；分子和分母的定义需要来源说明 |
| Delta CPP | 1 | 暂保留原字段，未查实验说明前不猜其含义 |
| Delta H-V | 1 | 暂保留原字段，未查实验说明前不猜其含义 |
| Delta S-H | 1 | 暂保留原字段，未查实验说明前不猜其含义 |

这些数量表明样本含有多种测量，不能统一按一个“数值越小越好”的规则分类。当前 11 条 IC50 也不是已经得到 11 个命中化合物。

## 8. 单位

`standard_units_counts` 同样按单位文本逐条计数：

| 单位 | 数量 | 含义和处理 |
|---|---|---|
| nM | 13 | 纳摩尔浓度；需要和具体测量类型一起理解 |
| uM | 1 | 微摩尔浓度；1 uM = 1000 nM |
| % | 3 | 百分比，不能换算成浓度 |
| mmHg | 1 | 压力单位，不能换算成浓度 |
| ms | 2 | 时间单位，不能换算成浓度 |

即使单位同为 nM，IC50、EC50、CC50 也不自动具有相同的科学含义。ChEMBL 的 `standard_` 字段表示来源已做过一定规范化，不意味着我们已经验证了本项目所需的实验兼容性。

“11 条 IC50”和“13 条 nM”是两组各自的统计，摘要没有给出它们的交集。必须查看每一行，才知道哪些 IC50 的单位是 nM。

## 9. 关系符号与如何使用边界

`standard_relation_counts` 按符号计数：`=` 14 条、`>` 四条、`<` 一条、缺失一条，总计 20 条。

等号表示记录报告了一个点值，不意味着测量没有误差或该点值必然有效。不等号提供的是范围。缺失符号则需要进一步审查。

下面是假设某个合适的 IC50 assay 已规定“IC50 ≤ 1000 nM 为命中”的教学例子。1000 nM 不是本项目已经确定的阈值：

| 来源结果 | 能否按这个示例规则判断 | 原因 |
|---|---|---|
| = 500 nM | 命中 | 点值落在阈值范围内 |
| < 500 nM | 命中 | 整个允许范围都小于 1000 nM |
| > 10000 nM | 非命中 | 整个允许范围都大于 1000 nM |
| > 100 nM | 暂不能判定 | 可能是 500，也可能是 5000，范围跨过阈值 |
| 数值缺失 | 暂不能判定 | 没有足够的测量信息 |

这里的非命中只针对已声明的实验与规则，不表示化合物在所有生物学情境下都无活性。正式数据整理还需要检查关系、单位、来源质量及兼容性。

## 10. assay 类型

`assay_type_counts` 按每条记录的 assay_type 计数，得到 A=6、B=6、F=8。这里统计的是 activity 记录数，不是 15 个不同 assay 各自所属类别的数量；同一个 assay 可能贡献多条记录。

ChEMBL 将 A 用于 ADME 类实验，B 用于结合类实验，F 用于功能类实验。ADME 涉及吸收、分布、代谢和排泄相关性质；功能类结果需要看具体生物系统和读出。

这些字母帮助我们选择下一步要检查的来源信息。B 类、IC50 字段或较高的目标映射置信度，都不能单独替代对实验方法的审查，也不能自动证明某个化合物直接结合了指定蛋白。

## 11. 质量注释

`data_validity_comment_counts` 返回 `<missing>:20`，表示这 20 条都没有该质量注释字段的非空内容。`<missing>` 是脚本为了便于统计显示的占位文本。

我们只能说没有看到该字段的标记，不能据此宣称记录全都可靠，或者重复、单位、实验兼容性、测量冲突已经处理完。

## 12. 五个输出文件各自保存什么

首次运行目录：

`/driveA/xinrong/agentic-screening/data/exploration/chembl_sample_20261013T154424Z_bf4ac0ff`

| 文件 | 保存内容 | 对项目的作用 |
|---|---|---|
| raw_status.json | 状态接口的原始响应 | 记录当时的数据库版本和状态 |
| raw_activities.json | 活性接口的原始响应 | 保留处理之前的证据，可以回头检查 |
| activity_preview.csv | 选出的 18 个字段 | 便于逐行查看化合物、目标、实验和测量 |
| summary.json | 刚才看到的统计摘要 | 快速发现需要进一步检查的字段与混杂问题 |
| run_metadata.json | 工具版本、脚本哈希、Python 版本、请求参数、时间、响应哈希、完成状态和错误信息等 | 追踪一次运行是怎样得到这些文件的 |

SHA-256 可用于检查对应字节内容是否改变，不是生物学可靠性评分。原始文件与摘要都需要保留；摘要不能代替原始记录。

用户 2026-10-14 提供的远程文件清单确认以上五个文件存在。这个存在性检查并没有逐行验证文件内容或比较哈希。

现在已经完成：远程访问、数据盘项目目录、Python 虚拟环境和基础依赖、一次真实状态查询、一次小样本读取与存档，以及理解统计摘要的准备工作。

以后数据构建智能体可以根据这些证据选择下一次查询或分析。当前脚本本身还没有这种 LLM 决策能力。原始结果属于数据构建和评价上下文，未来搜索智能体只能通过受控接口获得已查询结果，不能直接访问这里的全部活性文件。
