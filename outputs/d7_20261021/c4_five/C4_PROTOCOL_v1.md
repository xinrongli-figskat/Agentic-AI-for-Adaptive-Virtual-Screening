# C4 five-policy LLM arm — locked design before provider calls

Date: 2026-10-21. Post-exposure retrospective experiment; no new benchmark. CP-2 authorization is the user's 2026-10-21 message, limited to **TNAP × S_strong × bit**, two repeats × seeds 0–19 × four feedback decisions, nominally 160 decisions. DYRK3 and the other five proxies are excluded. The frozen TNAP pool has 462 compounds and 53 measured hits. Each campaign queries 50 distinct compounds: 10 label-blind initialization queries, then four batches of 10. The same seeds and initialization algorithm as C3 are used.

The five named policies and their order are byte-for-byte those of `C3_FIVE_MENU_SPEC_v1.md`: `greedy`, `diverse`, `random`, `persistent_random_until_first_hit`, `diverse_random_coldstart`. ENS is absent. This arm is named `llm_policy_only_five`. Selection uses the frozen `OrthogonalSelector` with `S_strong`; one-class states retain the authorized random fallback. A selected persistent policy commits subsequent zero-hit rounds to random without another GLM call, as in D5, and every such batch still uses 10 oracle queries. Automatic commitments and actual selection modes are logged.

The GLM receives the same 11 top-level summary fields as D5: `task`, `candidate_count`, `queried_count`, `remaining_budget`, `next_round`, `revealed_hits`, `recent_revealed_hits`, `numerical_summary`, `allowed_policies`, `policy_descriptions`, `commitment_note`. The numerical summary is computed from **S_strong** fitted only to revealed outcomes, not from the incumbent kNN: unqueried count, min/median/max predicted score, top-ten mean score, top-ten mean maximum Tanimoto similarity to already queried structures, and a score-availability flag. It contains no compound keys, SMILES, individual outcomes, or unrevealed labels. The only model tool is this policy-choice request; Python chooses actual compounds and the budgeted oracle reveals results.

Use the existing official client configuration for `glm-5.3-flash`: JSON-object response format, `do_sample=false`, reasoning enabled/low, `max_tokens=1024`, 120-second timeout, and the existing system prompt. The strict D5 parser is unchanged in substance: response must be a JSON object whose exact key set is `{policy, reason}`; policy must be on the five-item menu; reason must be nonempty and at most 1000 characters. An invalid format reveals no label. Save the raw response, returned usage, request ID, attempt log, elapsed time, and prompt hash in the private workspace; resend the **identical** public summary once. On a second invalid response at the same decision, abandon that repeat, record the failure, and move to the next repeat. Do not relax parsing or substitute a fixed policy. The bounded retry prevents selecting only campaigns that happened to have flawless formatting; the format-failure rate itself is a result. Provider transport errors pause the experiment without a substitute decision.

**Physical provider-call ceiling: 160 for this authorization.** The underlying client may retry model-overloaded HTTP errors, and format correction may consume another physical call; every transport opener invocation counts toward the 160 ceiling and is reserved in a durable private receipt *before* sending. If retries or automatic commitments change the number of completed decisions, report both physical and valid-decision counts. Stop at 160 physical attempts even if the 40 campaigns are incomplete; a higher ceiling requires a separate authorization. The cumulative D7 count was 361 before C4, so this ceiling keeps it at or below 521, under the 1,000 total cap.

Before any real call: lock this protocol, runner, relevant C3 core/selector/proxy code, GLM client and B-line analysis, frozen public/private pool hashes, five-menu CPU summary, and the additive tie correction by SHA-256 and UTC. The corrected six-point Spearman is −0.2898855 after rounding mean gaps to 0.01 and using average ranks for the tied 2.15 values; the old −0.20 was a floating-point rank artifact. Run a synthetic-label oracle test and mock HTTP request test, including the exact parser, menu, and no hidden-label prompt check. Store real trajectories and provider receipts only in a Git-ignored private directory. Existing D3–D7 records are never rewritten.

Primary comparison: the 40 C4 H@50 values versus the **C3 five-menu best meta-controller selected before C4**, `bandit_thompson` for TNAP × S_strong (mean H@50 13.15). For each seed, average its two LLM repeats, subtract the matched Thompson seed result, then average across 20 seeds. Use 10,000 paired seed bootstrap resamples with RNG seed 20261018. Also show a conservative B-line variance sensitivity by adding independent normal noise with SD `2.1943108257491692 / sqrt(40)` to each bootstrap mean; this can double-count some observed model noise, so it is a sensitivity interval, not a separate independent estimate. Report the paired bootstrap and augmented intervals side by side. If repeats are incomplete, do not silently impute; report the partial data and do not claim the planned primary comparison is complete.

Secondary comparisons: LLM minus the post-hoc best common fixed policy (`greedy`, mean H@50 16.65), and separately minus each of the three five-menu meta-controllers. Report all controller means, seed-paired effects, and uncertainty with the same method; secondary comparisons are exploratory and unadjusted. The maximum fixed-policy spread observed for this cell is 7.00 H@50, which bounds the available strategy-selection headroom descriptively; it is not a causal upper bound on every adaptive policy. No multiple-comparison correction is made because this is one post-exposure cell.

Map every selected **name** and every realized action to greedy-like, diverse-like, or random behavior, using the selector's actual mode and one-class fallback. Five names can collapse to three behaviors; the five-name uniform mixture effectively weights the duplicated greedy and diverse behaviors 40% each and random 20% in one-class states. This reference is not exactly uniform over behaviors. Under the tested fixed arm means, four of six TNAP proxy cells had the best CPU meta-controller below all common fixed means, but this does not prove switching caused the loss.

Interpretation is restricted to this single TNAP proxy/cell. C4 asks whether the LLM can recover the policy headroom left by the three CPU meta-controllers, **not** whether LLM benefit disappears as surrogate AUC rises (the mentor's question ii). It is not directly comparable with D5 `glm_extended` or D7-A bandits because menu and/or proxy differ. Existing D5 five-repeat results are historical context only. Hard stops: any menu-external selection, ENS decision, unrevealed label or individual compound outcome in the prompt, repeat query, query-budget overrun, changed frozen hash, or physical-call ceiling reached.
