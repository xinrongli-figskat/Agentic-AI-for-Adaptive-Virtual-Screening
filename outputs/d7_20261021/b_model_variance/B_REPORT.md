# D7-B：TNAP bit 的 GLM 运行间方差

本报告是 **post-exposure** 回顾性测量，不产生新 benchmark，也不提出新的 GLM 收益结论。TNAP v1 冻结池、D5 V0 七策略菜单、原 GLM 请求配置与 D5 严格 JSON 解析器均未修改。运行前完成输入、代码与失败点状态哈希锁定；旧 94 次物理请求及其格式错误完整保留。

## B1：重复与预算

20 个种子各有 5 次完整运行，共 100 组、每组 50 个不重复查询。其中 D6 已锁的 0–9 号种子各一次共 10 组作为首轮重复，其余 90 组是本轮新增。B 线新增 **361 次物理 HTTP 请求**，低于用户补订的 380 次上限：360 次有效模型决策，1 次 HTTP 200、但多出一个空 JSON 键而被原解析器拒绝的请求。该无效决策没有对应的 oracle 查询；相同状态、相同提示词哈希的下一次请求成功，部分运行从已保存的 20 次查询处恢复。无 HTTP 重试，也没有放弃的重复。全轮 600 次累计请求的强制报告点仍适用：B 后仅可再发 239 次请求，到 600 即停。

补订前的阻塞和补订后的恢复分别见 `BLOCKED_response_format_budget.md`、`B_ADDENDUM_AFTER_TIER_B.md` 和 `B_PROMPT_RECONSTRUCTION.json`。原请求体没有单独保存，故只能以一致的旧状态标记、未变的 D5 代码，以及恢复时逐次核对的重建请求体哈希，证明提示词的确定性重建，不能声称与原 HTTP 包做了历史逐字节对比。所有原始供应商响应、request ID、返回 usage、时延和失败事件均在 Git 忽略的私有目录。新增请求返回 token 合计 225,344（prompt 202,936；completion 22,408）；这是提供方用量，不是现金收费。

## B2：模型波动与五项历史比较

五次重复给出的种子内合并标准差 `SD_model = 2.1943` 个 H@50；20 个种子各自的样本标准差最小 0、中位 1.323、最大 7.225，显示波动并不均一。五次重复时，模型噪声对 20 种子均值的标准误为 `2.1943 / √(20×5) = 0.2194`。第 1 轮相同提示词下，五次重复的两两策略一致率为 123/200 = 61.5%；后三轮合并两两一致率约 35.8%，但输入状态已因前次决策分叉，不能把该数字全归因于模型随机性。

D6 的 4.20 是**两次运行 H@50 差值**在 10 个种子上的样本标准差，不是单次 `SD_model`。D5 原配对种子 bootstrap 曾把一次 GLM 实现混入种子差异；它不是完全漏掉模型随机性，但无法把两种方差分开。下面将历史效应与五次重复均值分列。区间是预锁的方差成分正态近似；重复结果的另一个预锁核对是每个 bootstrap 样本对每个种子随机取一次模型实现，见 `B_ANALYSIS.json`。没有多重比较校正。

## B3：续作门槛

按预锁公式，要使 20 种子的模型噪声均值 SE ≤0.5，最少需要 **1 次/种子**（`ceil(SD_model² / (20×0.5²)) = 1`），没有超过预定 5 次。因此 **B3 通过**。这只解除 D7-C LLM 臂的方差阻塞；C 还必须独立通过 CPU 强度排序和补订后的两项进入闸门。原第一轮模型决策一致率仅 61.5%，所以“方差门槛通过”也不等于决策可逐次复现。
