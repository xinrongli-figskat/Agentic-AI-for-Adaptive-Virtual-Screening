## 1. 项目的核心目标

在一个月内实现两个相互连接、能使用实际工具的 LLM 工作流程：

1. 数据构建智能体：寻找公开实验数据，判断哪些蛋白靶点适合研究，整理成可追溯、可重复使用的筛选 benchmark。
2. 主动搜索智能体：在固定 benchmark 中，依据逐步获得的实验结果，调整计算方法或选择策略，在有限查询预算内找到尽可能多的不同命中化合物。

研究问题可以表述为：在固定化合物池和查询预算下，允许 LLM 根据中间证据管理搜索，能够带来什么收益、成本和失败模式？答案需要实验支持；LLM 优于固定规则不是预设的完成条件。

这里的 retrospective benchmark 是已有实验结果组成的回顾性测试集。搜索时的 query 是揭示一个已存储的化合物结果，不代表开展一次新湿实验，也不等于调用一次 LLM。

## 2. Task 1：寻找和构建 benchmark

### 必须落实的工作

- 搜索公开生物活性数据，识别候选靶点，形成候选表及接受或拒绝理由。原文列举 PubChem BioAssay、ChEMBL、BindingDB，没有规定必须全部接入。
- 明确本 benchmark 对什么结果作出判断：例如某个生化 assay 下的活性，以及适用于该 assay 的命中标准。区分 assay 定义的命中与直接靶点结合的证据。
- 统一分子结构和测量单位；识别同一化合物的重复记录；处理冲突，以及 `>`、`<` 等只有边界信息的数值。不得把不等号记录直接当作精确值。
- 保存数据来源、assay、测量条件和处理规则；可检查一个标签是怎样形成的。
- 区分实验阳性、实验非活性、未知活性和人为分配的 decoy 标签。缺失测量不自动意味着非活性。
- 依据可用化合物数量、类别数量、化学多样性、类似物冗余、assay 兼容性以及搜索预算下的可行性，判断是否合格。
- 对合格数据集排序，选择可完成的 shortlist。优先由数据条件决定目标是否适合回顾性评价。
- 阴性数据不足时，可以拒绝目标，或提出明确标注、解释证据限制的 decoy 补充版本。合并 assay 时也需要说明解释依据。
- 在开发中以及正式评价前审查标准和关键取舍。结果出来后重新评估这些选择；一旦修改数据池或标签，生成新 benchmark 版本并重新开展相关实验。

### 如何体现这个流程的智能体作用

工具返回的数据会改变后续行动。例如，发现一个靶点的记录大量来自不兼容 assay，LLM 可以选择先检查 assay 条件；发现没有可靠非活性记录，可以选择搜索另一来源、评估 decoy 方案或拒绝这个靶点。标签转换、结构处理和统计由数值或数据工具执行，LLM 的选择需要记录依据。

### 应留下的产物

候选靶点与排名、资格标准、原始记录快照、整理规则、化合物池、私有结果表、来源表、排除与冲突日志、数据版本号及摘要。私有结果表和可泄露未查询活性的来源字段不能直接交给搜索智能体。

## 3. Task 2：反馈驱动的主动搜索

### 必须落实的工作

- 对选定 benchmark 使用固定化合物池和固定结果。
- 先声明总查询预算、初始化方式、初始化如何计入预算、每轮反馈节奏。
- 提供受控结果查询接口：查询指定化合物，只返回该化合物的存储结果；在接口中执行预算和去重规则。
- 搜索智能体初始可以访问允许的结构、特征和目标信息，随后只能获得已查询的结果。隔离数据构建上下文、私有结果文件和能够直接检索未查询活性的工具。
- 使用数值工具完成特征计算、评分、拟合、排序、校准或 acquisition 计算。
- 赋予 LLM 对后续行动有影响的决策权限：选择分析、模型或策略，依据已揭示反馈进行调整。
- 记录每次决策时可见的信息、工具调用、参数、选择结果、简要理由、错误与恢复动作。
- 统计不同命中化合物的数量，避免通过反复查询同一命中夸大收益。

### 初版可以采用的数值工具与策略

一个分子特征表示、一种简单分类模型、按预测命中概率选择，以及兼顾化学多样性的选择，已足以开始验证连接流程。没有观察到两类结果时，使用事先规定的探索或单类别回退策略，不能根据隐藏标签挑选阳性初始化样本。

ENS、复杂零样本模型、分子对接和 GPU 密集型方法可作为扩展。原文举例列出候选策略，没有要求每一种都实现。若采用零样本评分，需说明为何适合当前目标及数据；不能把尚未训练的二分类模型当成已具备可靠评分能力。

### LLM 决策的例子

若已查询样本长期只出现一类结果，选择分析已查询样本的结构覆盖并扩大探索；若反馈显示命中集中于某些类似物，检查冗余与化学覆盖，再选择继续局部利用或扩大覆盖。策略的具体切换规则与理由需要留痕，结果是否有效由后续评价回答。

## 4. 如何评价

| 项目 | 应记录或比较的内容 |
|---|---|
| 主要收益 | 随累计 query 数增长，找到多少个不同命中；声明预算结束时的命中数 |
| 参考策略 | 简单随机策略、贪心或多样性策略等可解释的基线 |
| 智能体作用 | LLM 控制器与规定规则的控制器使用相同工具、初始信息、预算和反馈节奏 |
| 重复实验 | 共用初始化与随机种子，展示不同重复下的变化；小样本比较不夸大统计结论 |
| 计算成本 | LLM tokens / API 费用、工具运行时间、CPU/GPU 使用和整体耗时，分别记录 |
| 失败模式 | 数据不足或冲突、单类别初始化、类似物过度集中、模型失效、工具错误、LLM 无效动作、标签泄露 |
| 数据解释 | 测量结果下的表现与 decoy 标签下的表现分别解释；不能据 decoy 恢复率推断真实非活性识别能力 |
| 针对性检查 | 检查关键冲突记录与 assay 合并；检查相似化合物冗余；验证隐藏标签不可见及预算执行；检查初始化和回退策略 |

正式评价前冻结标准、版本和控制策略。评价之后的反思、附加敏感性实验和数据修改应显式记录，保持主实验可追溯。

## 7. 计算与框架如何连接

LLM 提供决策；控制器管理状态与工具调用；科学工具执行计算；独立结果接口揭示已存储的单个化合物结果；独立评价器计算指标。

Tailscale 和 SSH 已解决笔记本访问实验室电脑的问题。它们尚未自动完成 Cloudflare 到实验室私网工具的访问。若沿用 Cloudflare，需要落实受控通信方式，不能假定 Worker 能直接调用 `100.x` 私网地址。

为了先验证科研流程，可以先在 Ubuntu 上运行两个分离的控制循环、科学工具和受限结果服务，调用云端 GLM；之后再对接 Cloudflare 的界面或调度。若既有 Cloudflare 框架已能方便接入，则可以继续复用。隔离应落实在工具、文件权限和服务边界上，不能只靠提示词要求模型不看答案。

## 8. 从现在开始的执行顺序

### 阶段一：建立项目环境与最小数据样本

确认数据盘个人目录可写，把项目、虚拟环境、大数据和模型缓存放到指定数据盘。检查现有环境后安装所需依赖。获取一份小规模真实实验数据，人工检查关键字段，再让数据构建智能体检查候选目标。

完成标志：能解释每条原始记录的化合物、目标、assay、测量值、单位与关系符号，候选表有实际数据统计。

### 阶段二：形成可冻结的 benchmark 和受控查询循环

制定数据资格与标签规则，落实标准化、去重与冲突处理，保存来源，形成版本化数据包。实现受控结果查询与预算，先用简单选择流程验证固定数据池下能够逐步获得反馈。

完成标志：真实数据跑通一次有预算的 campaign；未查询结果无法经搜索智能体的正常状态和工具取得。用于开发流程的小样本或合成样本不得冒充合格科学 benchmark。

### 阶段三：接入反馈模型、两个智能体与固定控制器

实现简单数值模型、贪心和多样性策略，以及单类别回退；加入分析工具与决策日志。数据构建智能体根据证据选择检索或整理动作；搜索智能体根据已查询反馈决定分析、模型或策略。固定控制器与 LLM 控制器共用工具接口及 campaign runner。

完成标志：可以逐条查看证据如何导致某次后续工具调用或策略选择；两条工作流程已经通过同一版本 benchmark 连接。

### 阶段四：冻结方案，比较并解释结果

评价前审查取舍并冻结配置。运行匹配的重复实验，绘制命中—查询曲线，统计成本，检查重要失败案例；开展少量直接回答关键疑问的针对性实验。反思标准与局限，任何修改以新版本记录。

完成标志：有可复现运行入口、数据和实验版本、曲线与成本表、决策轨迹及明确局限。按实际剩余时间分配各阶段；本对话没有确认正式截止日期，不把当前梳理当作重新开始一个月。
