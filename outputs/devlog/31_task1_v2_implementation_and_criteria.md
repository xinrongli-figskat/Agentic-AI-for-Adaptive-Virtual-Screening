# Task 1 v2 实现、资格分层和验证记录

日期：2026-10-15。对应 brief 的 Task 1：根据中间证据自主检索、选择后续审查动作、定义并解释数据资格、保留来源和决定。当前交付是新的搜索与整理软件，不是新 benchmark 的完成声明。

## 已实现

独立代码 `curation_agent_v2/`，不导入或改写原 `curation_agent_v1/`。复用并固定其数值整理工具副本，另写计数预筛、字段精简、证据分页、GLM 控制器和运行管理。

| 问题 | 新版实现 | 解释边界 |
| --- | --- | --- |
| 按哈希顺序对稀少目标抓取大量活动记录 | 先复用旧画像识别值得复查的目标，再逐目标 limit=1 取总数；不足下限就不抓窗口；在已计数目标中按数量排序 | 不是全数据库按可用化合物数排序；剩余目录仍按固定哈希次序计数 |
| 不清楚哪个 assay 可能同时覆盖两类 | 精简目标窗口按 assay 统计两类来源 ID 支持并排序；可单独查询 assay 目录与计数 | 不把来源 ID 或记录数当作标准化化合物数；部分窗口不能排除整个目标 |
| GLM 输入重复增长 | 默认只发精简状态、有限候选、最近动作；工具分页读实验说明、数值整理、记录或来源别名 | 输入 JSON 上限 24000 字符，不能保证具体 token 数或账单 |
| JSON 缺 verdict 等格式错误直接停 | 严格格式校验；保存原响应、错误和用量；最多两次纠正，期间不执行科学工具 | 三次连续无效即暂停；网络/HTTP 错误不按格式错误自动重试 |
| 500 被误认为 brief 要求 | 新版单独写资格审查和此前数据暴露清单；500 优先，250–499 有限可行性，其他门槛保留 | 改动发生于已看过旧结果后，不是盲态验证；旧拒绝结果不变 |
| 来源疑点被数量门槛掩盖 | p300/P2X 来源限制写入固定 registry；GLM 须完整读 assay 说明，再写端点和构建体/受体解释 | 没有自动批准原文/样品身份的工具；候选始终待审，campaign_ready=false |

GLM 的实际决策包括是否继续检索、读哪一项证据、是否完整获取、调用数值整理、判断实验含义以及拒绝/保留/列入待审草稿。数值计算、结构整理和门槛执行由程序承担。模型看不到无限制的文件或终端工具。

## 新资格规则的依据

500 原本是操作性门槛；brief 未规定具体数目。新最低层 250 使拟议 50 次查询不超过池的 20%；优先层 500 则不超过 10%。这只是对一个月技术可行性和剩余搜索空间的折中，不能据此声称具备足够统计功效或泛化能力。

两层都保留至少 30 命中、100 非命中、目标映射置信度 9、至少 10 个骨架桶、最大相似度簇 ≤25%、初始化单类别风险 ≤0.5、完整单 assay 数据等条件。精确规则和局限详见 `curation_agent_v2/CRITERIA_REVIEW.md` 与 protocol.json。

此前已见 DYRK3 的 231 个化合物与结果、60 个 Task 1 画像、p300/P2X 的数值整理和来源核对。新运行会固定 prior_exposure.json；不得将重新审查已见候选表述为独立发现。p300 368 个化合物并不会因最低层降到 250 自动入选；其样品/立体结构对应未解，仍阻断。P2X2/3 的受体身份与当前单蛋白范围不符，也不解除限制。

机器记录在 `task1_v2_validation/validation_receipt.json`、unittest.log 和 api_probe_20261015/。新版本尚未真实调用 GLM 搜索，所以不能报告搜索产率、真实 token 节省比例或成功入选数据集数。

## 接下来如何用

传输包：`task1_curation_agent_v2_transfer.zip`，独立安装器：`install_task1_v2.py`。安装器验证逐文件清单，只写两个新目录，拒绝覆盖已有不同内容。远端先运行 15 项测试，然后 prepare 创建新运行，执行不调用 GLM 的 32 个计数/至多 3 个精简画像；再按 README 的命令执行首批 8 个 GLM 工具动作。

真实新运行的结果应继续报告失败、零候选和费用。即使获得待审草稿，也要先核对来源身份和协议，再生成新的冻结版本、受控标签接口和 campaign；不得向旧 DYRK3 v1 注入新池或新标签。

本轮新文件已写入本机工作区；生成传输包不等于已保存到远端。前一次来源审查交付包同样须单独确认是否已上传。本包携带来源决定摘要与限制 registry，不包含全部原文审查原始资料。
