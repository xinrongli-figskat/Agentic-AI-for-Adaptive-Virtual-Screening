# 2026-10-15：Task 1 智能体实现与下一轮运行

## 为什么现在做

DYRK3 v1 已完成预定的实验与报告，但它仍是单实验、同系列的可行性原型。
原 brief 第一项还缺“LLM 根据证据决定下一次工具调用”的实际运行。
新增 `curation_agent_v1` 连接原有科学工具，填补这个功能缺口，继续寻找资格更充分的数据。

## 已实现

- GLM 从现有真实 discovery 摘要开始，选择继续发现目标、审查 assay 和文献元数据、完整获取单实验数据、数值整理、拒绝、候选排序与结束。
- 每次调用后将工具证据交回 GLM；数值资格不能被语言模型覆盖。
- 将结构标准化、重复/冲突/删失处理、未知不等于非活性等已测试逻辑保留为独立源码副本。
- 检索、证据、源码、协议、模型实际输入和原始回复保存；无效 JSON 的返回用量也在验证前保存。
- 有全局调用上限、逐步暂停、失败保存、继续运行、缓存和单写入锁。
- 合格数值候选可导出含 public/private 文件与哈希的版本化草稿；不自动冻结或开始 campaign。

## 科学条件变化

保留原工程门槛 500 个可用化合物、30 hit、100 nonhit。
为寻求比旧同系列原型更宽的化学覆盖，后续新任务另声明最大簇 <=25%、Murcko 桶 >=10、初始化单类别概率 <=0.5。
这是看过 DYRK3 v1 后制定的后续设计选择，并非 brief 固定要求，也不构成泛化保证。
这些条件可能过严，允许本次没有合格候选。改变条件须新建版本并解释原因。
不得据此重新描述或改动旧冻结 v1。

## 验证与证据边界

本地合成测试覆盖接受/拒绝分支、缺失标签、potential_duplicate 排除、不等号、冲突、结构合并、完整性门槛、哈希、调用预算、失败回复保存与继续运行。
另导入本地现有的真实 ChEMBL discovery 原始文件，验证完整目录重建与目标摘要重新计算。
这些不等于新 GLM 智能体已在真实数据上找到候选。真实账号调用将在远端执行，不能把本地合成结果写成科研发现。

当前范围仅 ChEMBL、单 assay IC50。只审查数据库描述和书目信息，不包含论文全文。
shortlist 是待协议审查的草稿；新 oracle、运行权限隔离、新冻结和后续 campaign 尚未部署。
DYRK3 v1 的数据、campaign 与报告保持不变。
