# D5 第二波：扩展菜单与对照规格（运行前）

日期：2026-10-20 UTC。性质：**post-exposure 新实验版本**，不是 DYRK3 v1/TNAP v1 原 campaign 的改写，也不是新的 benchmark。须先封存本规格、执行代码、池凭证与预检哈希，再读取本实验的任何真实结果。设计依据为同目录 `d5_wave1_synthesis.md`，其 A 组结果推翻了旧 `knn_diverse` 必然更孤立的推论。因此旧策略定义逐字节保留，新行为只作为新名字的菜单项测试。

## 共享池、表示与反馈

- 池：已冻结 DYRK3 v1（231 分子）和 TNAP v1（462 分子），均不修改。bit Morgan 半径 2、2048 位、手性为主；count 为独立敏感性表示。所有臂共享同一表示、公开结构、10 个无标签初始化候选、同种子 0–19、50 次不重复查询；之后每批 10 个，共四批。每批结果由既有 `BatchOracle` 揭示，未揭示标签不进入任何预测模型、GLM 提示词或公开候选特征。
- GLM 只在 TNAP 运行，模型与请求设置沿用 D4 的 `glm-5.3-flash`、`thinking=enabled`、`reasoning_effort=low`、`max_tokens=1024`、`do_sample=false`。最多 20 种子 × 两表示 × 四轮 = **160 个可决策时点**，并非保证 160 次收费 HTTP 调用；见下述持续规则。先完成 bit 种子 0–9 的 **40 个可决策时点**并核验，才执行其余。DYRK3 不调用 GLM。
- 每个新的预测分数只使用目前已揭示的标签拟合/更新；输入不包含库的总体命中率、近阈值私有信息、辅助 tid 深度或任何未查询结果。

## 数值工具菜单（所有控制臂共享）

| 名称 | 选择算法 | 冷启动与批内反馈 |
| --- | --- | --- |
| `knn_greedy` | **旧 v1 原函数**：加权 kNN 预测分数从高到低，原 seeded tie-breaking。 | 零命中也按旧公式；不改。 |
| `knn_diverse` | **旧 v1 原函数**：相同 kNN 减 `0.2×max Tanimoto`，逐个建立批内参照集。 | 零命中仍按旧公式；不改。 |
| `uniform_random` | **旧 v1 原函数**：按 seeded SHA-256 无放回选择。 | 每轮都可单独选。 |
| `persistent_random_until_first_hit` | 在累计零命中时调用旧 `uniform_random`；一旦本批首次揭示命中，下一轮回到开放菜单。固定单项臂此后使用旧 `knn_greedy`。 | **若 GLM 在零命中时选此项，承诺延续随机直到首个命中**；中间的选择时点不再重复调用 GLM，但每批照常消耗 10 次查询并记自动动作/理由。首个命中后的下一个时点恢复 GLM 选择。 |
| `diverse_random_coldstart` | 当前仍零命中时调用旧 `uniform_random`；已有命中时调用**未改动的**旧 `knn_diverse`。 | 与上项不同，它不建立持续承诺；每个时点都可重新选择。此项是新增的“零命中时不叠加多样性惩罚”，其效果尚未证实。 |
| `logreg_greedy` | 第二预测模型：仅用已揭示分子的同表示 Morgan 特征，`LogisticRegression(C=1, solver=liblinear, random_state=0)` 拟合二元结果，按预测命中概率取前 10，SHA-256 打平。 | 仅单类已揭示时按旧 `uniform_random` 探索并记录退化；不暗用隐藏标签决定模型。 |
| `ens_one_step_proxy` | 以旧 kNN 概率为后验近似，对每个候选考虑其 `y=0/1` 两种假想结果：`U_y(i)` 为该假想结果加入已揭示集后下一批前 10 个预测概率之和，`U_0`/`U_1` 按当前 `p_i` 加权。候选分数为 `p_i + 0.25×(E[U(i)]−U_now)`，取前 10；只读公开结构和已揭示标签。 | 为计算保护，只对当前 `p_i` 前 64 与 `p_i(1−p_i)×平均相似度` 前 64 的并集做看前一步计算；候选筛选规则与上限固定。当前批内的 10 个结果**全部未揭示**，独立评分时各自对 0/1 精确边际化，选择批次后不把任何幻想结果加入状态。忽略不同批内候选的信息重叠，故这是 ENS 式单步代理，**不是精确 ENS 或贝叶斯最优**。 |

旧三项必须继续调用旧 `NumericalTools.select_batch`，不得复制并悄悄改变排序。新菜单的描述提供给 GLM 和规定臂；GLM 只选策略名并给出依据，Python 决定具体分子。

## 对照与报告

- CPU 在**两个池**各跑 20 种子 × bit/count 的七个固定单项臂与 `random_mixture_extended`。固定单项臂始终请求相同菜单项，遇到该项定义内的冷启动回退则按上表执行。随机混合臂每个开放时点按预先固定 SHA-256 从七项**均匀**选一个；若选中持续随机且尚未命中，承诺持续到首个命中。所有臂的初始 10 个化合物应完全相同。
- `fixed_best_single` **事后**取七个固定单项臂在同池、同表示、20 种子的 H@50 平均值最高者；并列按菜单表顺序。它是乐观的事后参照，不可当作事前规定控制器或泛化证明。
- `matched_proportion_extended` **事后**按 TNAP GLM 的真实开放时点菜单比例建分布，在两池 CPU 运行。它检验粗略比例而非反馈时序；属于探索性，不能充当主结论地板。固定随机抽样种子与所有决策记录须存档。
- TNAP bit 的预定两项主比较为 `GLM_extended − fixed_best_single`（事后乐观参照，描述性）及 `GLM_extended − random_mixture_extended`（同工具、同初始化、同预算）。count 独立敏感性分析。次要比较为 `GLM_extended − D4 GLM_basic`、`GLM_extended − forced_random_coldstart`。DYRK3 仅报告 CPU 各臂相对旧冷启动与固定结果的描述性变化，尤其核查零命中初始化 0/20 时新冷启动项是否还有作用。
- 指标：H@50、累计 H@10/20/30/40/50、`queries_to_first_hit`（50 次仍未找到者右删失）、零命中及首命中后各菜单项次数、GLM/数值分析/选择耗时、HTTP 尝试、请求 ID 与返回 token。20 种子同种子配对均值和 10,000 次配对 bootstrap 95% 百分位区间（固定抽样种子 20261020）；差值分布按零命中初始化分层展示。D3 bit 的固定 − 强制冷启动配对 SD 9.17，20 种子的正态近似 95% 半宽约 4.02 命中，仅是量级提示；分布因零命中初始化而双峰。
- 多项比较没有家族错误率校正，结果只作本池 post-exposure 描述。若 `GLM_extended − random_mixture_extended` 的区间包含 0，结论写为“更大菜单没有使 GLM 的选择能力显现”。即使区间不含 0，也不据此宣称跨靶点、前瞻筛选或无污染的零样本收益。`fixed_best_single` 和匹配比例臂均事后构造，任何优劣须标明。

## 运行门槛与停止

1. 验证两个冻结池、旧控制代码、D4 依据与本规格哈希；合成标签下测试未查询标签不可见、重复查询拒绝、所有菜单项消耗预算；分数在合成结果置换时响应/无标签分数保持不变。**不以真实标签调参**。
2. 固定新代码 SHA-256 和请求配置；对模型用合成反馈做一次真实 API 探测，记录实际请求包含 `do_sample=false`、模型、返回 JSON、usage 与 request ID；该探测不计入 campaign 决策。
3. 先跑 TNAP bit 种子 0–9，核对 40 个可决策时点、实际模型调用数、每个 run 的 50 个唯一候选、未查询标签边界、费用与失败，才继续。发生失败则保存现场并暂停该 run；不得静默回退旧控制器。再跑 TNAP 其余 bit 与全部 count；CPU 臂可在规格与合成预检通过后运行。
4. 输出保持 campaign 私有轨迹与公开汇总分离，生成 MANIFEST/RUN_LOG/STATUS。任何标签、阈值、池或旧策略的改动属于另一版本；D5 不做。
