# Task 1 下一阶段：实施说明

日期：2026-10-16（上海时间）

## 这次具体做了什么

这次没有声称已经找到或建成新的 benchmark。它把 Task 1 的下一轮搜索准备成可审查、可限额的 v4 独立运行：先从已经留存并校验过的 ChEMBL 证据整理“下一步优先看哪里”，运行时再由 GLM 选择要画像的目标、检查的 assay、读取的证据或停止理由。计数、结构处理和资格门槛仍由程序计算；模型不能改门槛或把未知数据说成非命中。

离线队列来自已关闭的 v3 运行，包含 64 个目标的 IC50/type-B 记录量与 119 条 assay 预览。排在前面的未画像目标为 FAS（1864 条记录）、ATM（1630）、S1PR1（1474）、PAR4（840）和 GABA transporter 2（425）。这些数是数据库活动记录条数，不是独立化合物数，也不表示类别平衡。v4 每次向 GLM 展示前四个未画像目标及最多八条已有 assay 预览，再根据新工具结果更新决策上下文。

## 资格规则与解释边界

本轮保留 v3 已审阅的操作性规则：250–499 个整理后可用化合物作为有限可行性候选，500 个以上为优先；至少 30 个命中支持、100 个非命中支持；IC50 ≤1000 nM、confidence score ≥9、B 型单蛋白 assay、完整 assay 获取，并通过结构冲突、多样性、初始化及查询预算检查。campaign 方案仍为 50 次查询，其中 10 次初始化，50 次不超过池大小的 20%。

这些数字是本项目为一个月原型所定的筛选规则，不是 brief 的硬性要求，也不是普适科学标准。此轮继续搜索时不事后降低门槛；如将来要改，另建协议版本并在新 campaign 前确定。目标或 assay 的记录数、assay 预览的 molecule-ID 支持数，都不能直接充当最终标签。只有完整拉取、结构标准化、重复/冲突处理、来源核对后，才可形成可冻结的数据集。

所有已有数据和 DYRK3 结果都已被看过，因此 v4 是 post-exposure 探索，不能声称盲验证或独立复现。已有 p300 与 P2X 来源保留决定仍只针对相应 assay，不自动排除整类蛋白目标。

## 运行步骤与停点

1. 将 transfer ZIP 与安装器放到远端项目目录，先核对 SHA256，再运行安装器。安装器逐个验证归档成员哈希，并拒绝覆盖已经存在的 v4 目录。
2. 先运行 `prepare --check-only`。它校验已关闭的 v3 运行、数据证据和软件环境，预览新目录及预算；不发 ChEMBL 请求、不调用 GLM，也不创建运行目录。
3. 预检结果确认沿用原始 v3 运行后，再运行正式 `prepare`。新目录继承旧记录，不改写 v3；这轮最多新增 12 次 GLM 决策和 100 次 ChEMBL HTTP 请求。累计上限是 72 次 GLM 尝试、213 次 HTTP 请求（其中分别包含 v3 已发生的 60 次与 113 次）。
4. 首轮最多执行 8 个决策。检查每个 action、引用的 evidence ID、工具错误、LLM/HTTP 消耗及新增计数，再决定是否继续剩余预算。模型格式纠错、失败请求也会占用预算并留痕。
5. 只有候选 assay 满足规则且来源、样本身份、终点和标签处理完成后，才能另行建立新的冻结数据版本并评估 Task 2。数值 shortlist 仍只是待审稿，不是 benchmark。

## 与 brief 的对应关系

此 v4 直接补强 Task 1 的“搜索来源、结合中间证据选择下一次工具、记录科学判断与淘汰理由”要求，也减少在小目标上的无效读取。它还保留了 assay 端点和来源解释边界。它没有替代完整 benchmark 构建，也没有新增 Task 2 campaign；Task 2 目前仍是 DYRK3 小规模可行性原型。下一步的成功标准是获得至少一个可完整复核的候选数据集，或者用清晰的证据与搜索范围说明本轮仍无合格候选。
