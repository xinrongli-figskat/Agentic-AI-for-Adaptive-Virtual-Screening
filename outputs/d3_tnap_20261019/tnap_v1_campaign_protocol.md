# TNAP v1 CPU campaign protocol — D3-4

Date: 2026-10-19 UTC. Post-exposure feasibility comparison, not blind validation. This protocol is locked before any TNAP CPU campaign results. No GLM arm is run in D3; GLM belongs to D4. Frozen TNAP v1 receipt SHA-256: `f8801efbe28f73ddbcf9c5a2d493d862cbf124f311b6659e9224f2161b5bf662`. The pool is assay-defined human TNAP inhibition from PubChem AID 1056 / ChEMBL CHEMBL1738510. Source class `limited`: construct unspecified and measurement depth differs across compounds, strongly associated with the label (AUC 0.8785, r 0.4949). It measures differently characterized actives versus thinner-measured nonhits, not a uniform-effort screen. It does not demonstrate direct binding.

## Fixed design

- The same frozen 462-compound pool and 53/409 labels are used by every arm. Threshold is fixed at IC50 ≤1000 nM. No candidate, label, endpoint, threshold, representation, seed, or arm is changed after looking at TNAP campaign results. Structure–label association is an evaluation, not an admission gate.
- Each seed uses 50 unique queries, including 10 unlabeled initialization selections followed by four feedback batches of 10. Oracle reveals an entire batch only after submission. Seeds are 0–19. Initialization is `SHA256("init|" + seed + "|" + compound_key)` ascending, first 10, shared across arms and representations; there is no redraw or hidden-label stratification.
- Main representation: Morgan radius 2, 2048-bit, chirality-enabled bit fingerprint. Sparse Morgan count fingerprint with same radius and chirality is a separately reported sensitivity analysis. RDKit Tanimoto is used for both. kNN uses five nearest revealed compounds, squared-Tanimoto weights and Beta-smoothed base rate with prior weight 2. Diversity policy subtracts 0.2 times maximum similarity to queried plus within-batch selections. Greedy ties use `SHA256("tie|seed|round|compound_key")`; random continuation uses `SHA256("random|seed|round|compound_key")`.
- TNAP prevalence 53/462 implies exact P(no hit in unlabeled initialization)=0.2919109424; P(single class)=0.2919109426, so about 5.8 of 20 seeds are expected to start with no hit. This known risk is accepted. All primary arms follow their declared policy without an implicit zero-hit override: nonhit observations still give the existing kNN novelty preference. Explicit `forced_random_coldstart` measures the alternative, consuming ordinary queries until the first revealed hit, then returning to greedy. D3-0 spec SHA-256 `9fd66ccb5606276349623c10fa60a5fe7bad3082293f04ccad349c2621a6f552`.

## Arms, all using the same batch oracle and budget

1. `random`: uniform deterministic seeded random policy in all four feedback rounds.
2. `structure_prior`: compute public-only `mean_tanimoto_k5` to five nearest other pool compounds for each representation before loading labels. Select descending score after shared initialization; ties by `SHA256("structprior|seed|round|compound_key")`. Selector takes neither revealed outcomes nor label file. D1 descriptor spec SHA-256 `2b59e83b01f35ed5cd43505518517ad25920beee8bc06f83f4afab08706708c3`.
3. `label_shuffle`: use the existing D1 full-pool seeded permutation of 53 hits and 409 nonhits for the controller-facing oracle, preserving the category multiset. Greedy kNN uses those permuted observations; true labels are used only by the separate evaluator. The true labels are not supplied to the controller or numerical tool.
4. `fixed`: prescribed `knn_greedy` every round, with no zero-hit override.
5. `fixed_schedule`: `knn_greedy, knn_greedy, knn_diverse, knn_greedy` in rounds 1–4, with no zero-hit override.
6. `rule_adaptive_v2`: first feedback batch is greedy. For later batches, choose diverse iff most recent completed batch's hit count is strictly below the mean of all earlier completed batches, including initialization. No hidden cold-start override. Decision mapping follows D2 v2 spec SHA-256 `6d7d54a8ae84a53916f151c74249451d486993ccd6e7814818c1d18df126951a`; the removal of its original fallback is the declared D3-0 deviation.
7. `forced_random_coldstart`: otherwise fixed greedy, but uniform random while cumulative revealed hits are zero. This is a secondary, explicitly separate arm; every fallback batch uses ten of the 50 queries.

`matched_proportion` is deferred to D4 because TNAP has no observed GLM policy mixture to match. D3 does not substitute the DYRK3 policy proportions. No LLM calls and no model token cost.

## Comparisons and interpretation locked before runs

Main bit-fingerprint contrasts are paired seedwise `fixed − structure_prior` (incremental effect of outcome feedback plus kNN mechanism) and `fixed − label_shuffle` (correct-label incremental effect). Secondary contrasts are `rule_adaptive_v2 − fixed`, `fixed_schedule − fixed`, `forced_random_coldstart − fixed`, and each arm minus random; count representation is sensitivity only. H@50 is the primary metric. For each contrast use 10,000 paired-seed bootstrap resamples with RNG seed 20261018, report mean and percentile 95% interval; only a reported interval excluding zero is described as an observed difference, without broad generalization. The D3 comparisons do not establish an independent GLM benefit.

Random expected H@50 is 50×53/462=5.7359307359, leaving 44.2640692641 hits above random to the theoretical 50-hit ceiling, versus about 24.9 in DYRK3. This larger absolute dynamic range does not establish statistical power: the TNAP paired SD is unknown beforehand. Report it after runs, plus post-hoc detectable-effect context, without changing main contrasts.

Report each arm's cumulative hits after 10/20/30/40/50 queries, mean cumulative hits over 10–50 using trapezoidal area divided by 40, H@50/random expectation, and queries to first true hit. Report no-hit initialization seeds separately, their per-arm H@50 and first-hit query, and forced fallback versus fixed. Report `rule_adaptive_v2` trigger counts and rounds separately for bit/count, without reusing DYRK3 trigger predictions. The [800,1250] nM exact-value near-threshold re-score is descriptive only and does not alter any trajectory or frozen label. Record feature-build, selection, analysis, data-acquisition and total wall time; GLM calls/tokens are zero. Unknown timings are labeled unknown.

Before real labels are queried, D3-5 must verify the synthetic oracle boundary, label-shuffle true/model separation, structure-prior invariance under a random permutation of outcomes for all 20 seeds, D3-0 zero-hit monotonicity, shared seed initialization, and all frozen/code hashes. Any failed preflight is a hard stop. All compound-level trajectories and revealed labels stay in a `_private_` path; public reports contain aggregate statistics only.
