# DYRK3 v1: single-assay active-search feasibility protocol

Decided before any real-label campaign on 2026-10-15. The curation team has already seen some labels and edge-case IC50 values; this is a retrospective feasibility prototype, not a blind external validation or a general benchmark.

**Pool and endpoint.** ChEMBL 37, human DYRK3 `CHEMBL4575`, enzyme assay `CHEMBL5363961`, IC50. The assay-defined hit criterion is IC50 at or below 1000 nM; nonhit means a measured or supportable assay outcome above that cutoff, not absence of binding. The one ChEMBL `potential_duplicate=1` compound is excluded and retained as unknown. There are 231 queryable compounds, 116 hit-supported and 115 nonhit-supported. No decoy labels are used. A ChEMBL source audit and original qualification decision are retained separately in the curation workspace. This pool fails the original 500-compound priority gate; it is accepted only as a single-assay, same-series workflow prototype.

**Query protocol.** Five preselected seeds `0,1,2,3,4`. Each controller and representation uses the same seed-specific label-blind initialization: sort public compound IDs by SHA256 of `init|seed|compound_key` and query the first 10. Four subsequent batches query 10 distinct compounds each, with feedback after each full batch. Total budget is 50 distinct compounds including initialization. No repeats or out-of-pool IDs. No seed replacement if initialization contains only one class.

**Numerical tools and controller comparison.** Main representation is Morgan radius 2, 2048-bit, chirality-aware bit fingerprint. Weighted kNN uses five nearest revealed examples, squared Tanimoto weights, a Beta-smoothed observed hit prior and prior weight 2. The greedy policy takes highest predicted hit scores. The diverse policy subtracts `0.2 ×` maximum similarity to the already queried and current-batch selected compounds. Equal scores use SHA256 of `tie|seed|round|compound_key`; random selection uses SHA256 of `random|seed|round|compound_key`. The predeclared secondary representation uses sparse Morgan count fingerprints with the same radius, chirality, scoring and budget. Both representations retain distinct compound identities even when bit fingerprints tie.

The fixed controller always uses `knn_greedy`; the random reference continues uniformly without replacement after the same initialization. The LLM controller uses official Zhipu `glm-5.3-flash`, JSON policy choice, thinking enabled, low reasoning effort, `do_sample: false`, max 1024 output tokens and a 120-second request timeout. It sees the candidate and unqueried counts, all already revealed outcomes, recent hit counts, a numerical summary of kNN score spread and similarity to observed compounds, and the allowed policy descriptions; it chooses one of `knn_greedy`, `knn_diverse`, `uniform_random` each feedback round and gives a short rationale. Python computes scores and chooses IDs. The model has no arbitrary file, shell, retrieval or oracle tool. A provider `1305` model-overload error permits at most two retries of the same decision request after 5 and 15 seconds, respectively (three attempts total); each HTTP attempt is logged. A 120-second network read timeout is logged as one attempt and is not retried automatically because the provider may already have processed it. Other API errors, exhausted overload retries, timeouts, or invalid output stop before the next query; a saved checkpoint may be resumed without repeating model decisions for completed rounds. There is no silent fallback to the fixed controller.

**Model choice before freeze.** The earlier `glm-4.7-flash` endpoint returned one successful synthetic decision, two `1305` model-overload responses and a 60-second read timeout. An initial `glm-5.3-flash` synthetic call returned `1210` while the shared client requested disabled thinking; its model documentation says only enabled thinking is supported. With enabled thinking, low reasoning effort and 1024 output tokens, a new synthetic call succeeded once (HTTP 200; 486 prompt and 45 completion tokens) and returned an allowed policy. Before freezing, `do_sample: false` was added to reduce generation variability, using a documented parameter; the exact final request is to be synthetically probed again. The choice of `glm-5.3-flash` is for demonstrated request compatibility and practical access to the available gifted resource, not because its decision quality has been established. This choice and request profile precede any real-label campaign. One successful call does not guarantee future availability; failed calls remain recorded and no model substitution is allowed inside v1. The source of the model-specific parameter rule is https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash; the sampling parameter is documented at https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E5%AF%B9%E8%AF%9D%E8%A1%A5%E5%85%A8.

**Prespecified evaluation.** Primary result is distinct hits recovered at 50 queries, `H@50`. Primary comparison is the paired LLM-minus-fixed difference for the **bit-fingerprint main representation** at each matching seed; report its mean and sample standard deviation, and paired LLM-minus-random differences. The count-fingerprint representation is a separate sensitivity result and must not be pooled into the primary mean. Secondary measures are cumulative hits at 10,20,30,40,50; each batch's new hits; and the trapezoid area under cumulative-hit curve from 10 to 50 divided by 40 (average cumulative hits over that interval). Report API request IDs, all HTTP attempts and overload rejections, prompt/completion/reasoning tokens when returned, model latency including retry waits, fingerprint build, numerical analysis and acquisition time separately. Record failed decisions and their attempted requests and elapsed time across resumptions; token use for timed-out requests is unknown unless independently reported by the provider. No GPU screening model is used in v1. Record HTTP failures and incomplete campaigns; do not count failed requests as successful queries.

**Threshold sensitivity.** Keep the 1000 nM labels fixed. After all primary campaigns, mark exact IC50 values in the inclusive `[800,1250] nM` interval as near-threshold; the interval is log-symmetric by a factor of 1.25 and is not an estimated experimental error. Report queried near-threshold count and hits, and hits among exact measurements outside the interval. Censored measurements are not assigned an exact distance and are reported separately. This is descriptive re-scoring of the same queries, not a new 50-query campaign. A different candidate pool requires a new version and full rerun.

**Interpretation and deviations.** One paper/series, high hit prevalence (~50%), 50/231 queried, analogue concentration (largest cluster ~31%) and bit-fingerprint collisions limit generalization. Random `H@50` expectation from the full measured pool is ~25.1; paired differences and variance matter more than raw hit count. Evidence is assay-defined DYRK3 inhibition, not proof of direct binding. If any pool, label, code, model, schedule or metric changes after this freeze, record it as a deviation or create a new version before using the revised result.
